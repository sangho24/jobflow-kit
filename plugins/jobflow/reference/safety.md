# 안전 원칙 (정본)

모든 jobflow 스킬이 따르는 원칙이다. 스킬 본문과 충돌하면 이 문서가 우선한다. 각 항목 끝에 이유를 한 줄로 적는다.

## 지원서

- **제출 버튼을 누르지 않는다.** 임시저장까지만 한다. 최종 제출은 항상 사용자가 직접 한다. 이유: 제출은 되돌릴 수 없고, 잘못 들어간 값 하나가 서류 탈락으로 이어진다
- **값을 지어내지 않는다.** 프로필에 없는 값은 빈칸으로 두고 노션 행의 `## 5. 결정 필요` 목록에 올린다. 이유: 틀린 값으로 제출된 지원서는 사용자가 알아채기 어렵다
- **문장(자소서)은 대신 쓰지 않는다.** 방향, 소재, 구조, 질문까지만 돕고 문장은 사용자가 쓴다. 이유: 자소서는 본인의 말이어야 하고, 대필은 면접에서 드러난다
- **경험 카드에는 사용자가 말한 것만 적는다.** 추측으로 성과나 수치를 보태지 않는다. 이유: 부풀려진 경험은 면접 질문에서 무너진다
- **검색, 드롭다운, 연동 select 필드에 텍스트를 주입하지 않는다.** 학교, 전공, 자격증, 지역처럼 목록에서 골라야 하는 필드는 사용자에게 넘긴다. 이유: 겉으로는 채워져 보여도 내부 코드값이 잡히지 않아 빈 값으로 제출된다

## 계정과 인증

- **본인인증, 캡차, 2단계 인증을 우회하지 않는다.** 만나면 멈추고 사용자에게 넘긴다. 이유: 사용자 본인만 통과해야 하는 장치이고 우회는 계정 정지 위험이 있다
- **이메일 인증코드는 기본적으로 멈추고 사용자에게 받는다.** 사용자가 그 세션에서 "메일에서 찾아서 넣어줘"처럼 명시적으로 요청한 경우에만 Gmail 커넥터로 그 코드 하나를 읽어 입력할 수 있다. 다른 메일은 읽지 않는다. 휴대폰·PASS 본인인증, 캡차, 2단계 인증 앱은 예외 없이 사람 몫이다. 이유: 메일함은 개인정보 덩어리라 열람 범위를 사용자가 정해야 하고, 휴대폰 기반 인증은 본인 확인 그 자체다
- **자동 회원가입을 하지 않는다.** 계정이 필요하면 `계정 상태` 를 `생성필요` 로 두고 사용자에게 알린다. 이유: 가입에는 약관 동의와 개인정보 제공이 따르고 그 판단은 본인의 몫이다
- **비밀번호는 OS 보안 저장소(macOS 키체인)에만 둔다.** 파일, 노션, 로그, 메일, 대화에 쓰지 않는다. 명령줄 인자로도 넘기지 않는다(셸 기록과 프로세스 목록에 남는다). 키체인 저장은 사용자가 터미널에서 직접 대화형으로 입력하도록 안내한다. 로그인에 실패하면 재시도하지 않고 사용자에게 알린다. 이유: 재시도는 계정 잠금으로 이어지고, 평문 저장은 유출 통로가 된다
- **봇 차단을 우회하지 않는다.** User-Agent 위조, Turnstile 같은 챌린지 우회를 하지 않는다. 막히면 "사람이 열어야 함"으로 표시한다. 이유: 서비스 약관 위반이며 계정과 IP 에 불이익이 갈 수 있다. 단, 표시만 하고 끝내지 말고 트래커에서 누락되지 않게 추적 대상으로 남긴다

## 공고 판정과 트래커

- **자격은 공고 원문 문장으로만 판정한다.** 직무명이나 채용 집계 사이트의 요약으로 판정하지 않는다. 이유: 같은 직무명도 회사마다 연차와 학력 요건이 다르고, 요약은 틀리는 경우가 있다
- **마감일은 비워 두지 않는다.** 확인되지 않으면 잠정 목표일을 넣고 `마감 유형` 을 `잠정` 으로 한다. 유일한 예외는 비고 첫 줄이 `❌ 자격 미달 확정` 인 행으로, 달력에서 빼기 위해 마감일을 비운다. remind 의 "마감일 확인 필요" 경고는 이 행과 `마감 유형 = 상시` 행을 제외한다. 이유: 마감일이 빈 행은 달력과 알림에서 사라져 놓치지만, 지원할 수 없는 공고는 오히려 달력에서 빠져야 한다
- **마감이 지난 `지원 전` 건을 자동으로 `공고마감` 처리하지 않는다.** 사용자에게 묻는다. 이유: 마감일 오기재나 연장일 수 있고, 한 번 닫으면 다시 안 보게 된다
- **같은 알림을 하루에 두 번 보내지 않는다.** 이유: 반복 알림은 곧 무시되어 정작 급한 알림을 놓치게 한다
- **스크린샷은 노션에 올리지 않는다.** 로컬 `snapshots/` 에만 둔다. 이유: 카톡 캡처 등에는 제3자의 이름과 대화가 들어 있을 수 있다

## 수집과 개인 데이터

- **공고 수집에는 robots.txt 를 존중한다.** 다만 본인 계정으로 본인 지원서를 쓰는 것은 크롤링이 아니므로, 지원서 작성 단계의 브라우저 조작에는 robots.txt 를 적용하지 않는다. 이유: robots.txt 는 대량 수집을 다루는 규칙이고, 개인이 자기 지원서를 작성하는 행위와 성격이 다르다
- **개인 데이터는 작업 폴더와 사용자 노션 밖으로 보내지 않는다.** 프로필, 경험 카드, 주민번호, 연락처, 주소는 외부 서비스, 제3자 도구, 플러그인 제작자에게 전송하지 않는다. 노션과 보고서에는 주민번호, 주소, 전화번호 같은 민감 값 대신 `(입력함)` 만 적고, 비밀번호는 아예 적지 않는다. 이유: 한번 나간 개인정보는 회수할 수 없다
