# 노션 트래커 구조

`/jobflow:setup` 이 사용자 노션에 만드는 구조의 정본이다. 모든 스킬은 여기 적힌 속성 이름과 선택지를 그대로 쓴다. 속성 이름이나 선택지 문구를 바꾸면 intake, remind, apply 가 어긋난다.

## 전체 구조

```
📡 취업 준비 트래커 (페이지)
├── 🗓️ 채용 일정 (인라인 DB)  ← 자동화의 중심. 모든 공고는 여기 한 곳에만 기록
│     뷰: 달력 / 🎯 지원 대상 / 진행 중 / 지원 결과
└── 📚 취업 스크랩 (인라인 DB)  ← 공모전, 특강 같은 보조 자료
```

「진행 중」과 「지원 결과」는 별도 DB 가 아니라 채용 일정의 필터 뷰다. 한 곳만 갱신하면 모든 뷰가 함께 바뀐다. 같은 공고를 두 군데 기록하지 않는다.

## 채용 일정 DB 속성

| 속성 | 타입 | 선택지 또는 용도 |
|---|---|---|
| 기업명 | title | |
| 직무 | text | |
| 모집 유형 | select | 체험형인턴 / 채용형인턴 / 공채 / 수시채용 / 경력채용 / 계약직 / 파트타임 |
| 진행 상태 | select | 지원 전 / 서류제출 / 필기전형 / 면접전형 / 서류합격 / 필기합격 / 면접합격 / 최종합격 / 서류탈락 / 필기탈락 / 면접탈락 / 공고마감 |
| 우선순위 | select | 높음 / 중간 / 낮음. 빈 값은 원문 검증 전이라는 뜻 |
| 자동화 상태 | select | 미시작 / 조사완료 / 입력완료 / 검토대기 / 차단됨 |
| 마감일 | date | 비워 두지 않는다 |
| 마감 유형 | select | 확정 / 상시 / 잠정 |
| 지원 페이지 | url | 원본 ATS URL (집계 사이트 링크가 아니라 지원 시스템 주소) |
| ATS | select | recruiter.co.kr / Greenhouse / Lever / Workday / Greeting / careerlink / 인크루트 / 자체구축 / 미확인 |
| 계정 상태 | select | 불필요 / 생성필요 / 보유 |
| 지원일 | date | 제출한 날 |
| 비고 | text | 첫 줄에 결론 표식 |

비고 첫 줄 표식: `🔴 미확인`(원문 검증 전), `❌ 자격 미달 확정`, `⚠️`(주의 사항), `📸`(스크린샷 기반 등록).

## 취업 스크랩 DB 속성

| 속성 | 타입 | 선택지 또는 용도 |
|---|---|---|
| 이름 | title | |
| 유형 | select | 공모전 / 해커톤 / 특강 / 합격자료 / 기타 |
| 링크 | url | |
| 마감 | date | |
| 메모 | text | |

## 생성 방법 (노션 커넥터)

노션 커넥터의 도구 이름은 환경에 따라 다를 수 있다. 도구가 안 보이면 ToolSearch 로 `notion` 을 검색한다(`reference/connectors.md`). 아래는 기능 기준 절차다.

1. 페이지 생성: 사용자가 정한 부모 페이지 아래에 제목 `📡 취업 준비 트래커` 로 만든다. 부모를 정하지 않았으면 개인 페이지(private)로 만든다
2. 채용 일정 DB 생성: 아래 DDL 을 쓴다. 부모는 1번 페이지, 인라인으로 만든다
3. 취업 스크랩 DB 생성: 같은 방식
4. 두 DB 를 조회해 데이터 소스 ID(`collection://...`)를 얻고 config.yaml 의 `notion` 에 기록한다
5. 채용 일정 DB 에 뷰 4개를 만든다

### 채용 일정 DDL 예시

```sql
CREATE TABLE (
  "기업명" TITLE,
  "직무" RICH_TEXT,
  "모집 유형" SELECT('체험형인턴':gray, '채용형인턴':blue, '공채':green, '수시채용':yellow, '경력채용':purple, '계약직':orange, '파트타임':pink),
  "진행 상태" SELECT('지원 전':gray, '서류제출':blue, '필기전형':blue, '면접전형':blue, '서류합격':green, '필기합격':green, '면접합격':green, '최종합격':green, '서류탈락':red, '필기탈락':red, '면접탈락':red, '공고마감':default),
  "우선순위" SELECT('높음':red, '중간':yellow, '낮음':gray),
  "자동화 상태" SELECT('미시작':gray, '조사완료':blue, '입력완료':green, '검토대기':yellow, '차단됨':red),
  "마감일" DATE,
  "마감 유형" SELECT('확정':green, '상시':blue, '잠정':yellow),
  "지원 페이지" URL,
  "ATS" SELECT('recruiter.co.kr':gray, 'Greenhouse':green, 'Lever':blue, 'Workday':orange, 'Greeting':purple, 'careerlink':pink, '인크루트':yellow, '자체구축':brown, '미확인':default),
  "계정 상태" SELECT('불필요':gray, '생성필요':yellow, '보유':green),
  "지원일" DATE,
  "비고" RICH_TEXT
)
```

### 취업 스크랩 DDL 예시

```sql
CREATE TABLE (
  "이름" TITLE,
  "유형" SELECT('공모전':blue, '해커톤':purple, '특강':green, '합격자료':yellow, '기타':gray),
  "링크" URL,
  "마감" DATE,
  "메모" RICH_TEXT
)
```

DDL 문법이나 색 이름이 커넥터 버전에서 거부되면, 색 지정을 빼고 `SELECT('a', 'b')` 로 다시 시도한다. 생성 뒤에는 반드시 DB 를 조회해 속성과 선택지가 위 표와 같은지 확인한다.

## 뷰 4개

DB 생성 직후에는 기본 표 뷰 하나만 있다. 뷰 생성 도구로 아래 넷을 만든다. 기본 표 뷰는 이름을 `전체` 로 바꾸거나 그대로 둔다.

| 뷰 이름 | 형태 | 설정 |
|---|---|---|
| 달력 | calendar | 날짜 속성 `마감일` 기준 |
| 🎯 지원 대상 | table | 필터: `진행 상태` = 지원 전. 정렬: `마감일` 오름차순 |
| 진행 중 | table | 필터: `진행 상태` 가 서류제출, 필기전형, 면접전형, 서류합격, 필기합격, 면접합격 중 하나 |
| 지원 결과 | table | 필터: `진행 상태` 가 서류탈락, 필기탈락, 면접탈락, 최종합격 중 하나 |

뷰 필터 지정이 도구에서 막히면 뷰는 만들되 필터는 사용자에게 노션 화면에서 직접 걸도록 안내한다. 이 경우에도 데이터 기록에는 영향이 없다.

## 행 본문 템플릿

공고 한 건의 페이지 본문은 다음 섹션으로 시작한다. intake 가 1번을 채우고, 나머지는 다른 스킬이 채운다.

```markdown
## 1. 공고
(담당 업무 / 지원 자격 / 우대 사항 / 채용 일정 원문 요지와 출처 URL)

## 2. 자기소개서
(문항별 방향과 소재. 문장 자체는 사용자가 쓴다)

## 3. 준비 항목
- [ ] 이력서 최신화
- [ ] 자소서 초안
- [ ] 첨부 서류 확인

## 4. 입력 내역
(apply 가 자동입력한 항목과 값 요약. 비밀번호와 주민번호 같은 민감값은 적지 않는다)

## 5. 결정 필요
(자동입력 중 값을 지어내지 않고 남겨 둔 항목, 사용자가 직접 골라야 하는 항목)
```

fit 은 본문 맨 아래에 `## JD 분석 (YYYY-MM-DD)` 섹션을 덧붙인다.

## SQL 조회 예시

노션 커넥터의 데이터 소스 조회 도구는 SQL 모드를 지원한다. 컬럼은 큰따옴표로 감싼다. 날짜 속성은 원래 이름으로는 접근되지 않고 확장 컬럼으로만 접근된다.

- `"date:마감일:start"`: 마감일 시작
- `"date:마감일:end"`: 마감일 종료
- `"date:마감일:is_datetime"`: 시각 포함 여부
- 지원일도 같은 방식: `"date:지원일:start"`

```sql
-- 지원 전 건을 마감 임박 순으로
SELECT "기업명", "직무", "date:마감일:start" AS "마감", "우선순위", "url"
FROM "<jobs_ds>"
WHERE "진행 상태" = '지원 전'
ORDER BY "date:마감일:start" ASC
```

```sql
-- 오늘부터 7일 안에 마감되는 지원 전 건
SELECT "기업명", "직무", "date:마감일:start" AS "마감"
FROM "<jobs_ds>"
WHERE "진행 상태" = '지원 전'
  AND "date:마감일:start" BETWEEN '<오늘 YYYY-MM-DD>' AND '<오늘+7일 YYYY-MM-DD>'
```

`FROM` 에 들어가는 이름은 config.yaml 의 `jobs_ds` 값(`collection://...`)이다. 도구의 안내에 따라 따옴표 형식을 맞춘다.

## 쓰기 주의

- 새 공고 행: 페이지 생성 도구에 부모로 `data_source_id` 를 지정한다
- 속성 갱신: 페이지 갱신 도구의 속성 갱신 명령을 쓴다. 본문은 삽입 또는 검색 치환 명령으로 고친다
- 날짜 속성은 확장 키로 쓴다: `"date:마감일:start": "2026-12-31"`, `"date:마감일:is_datetime": 0`
- `is_datetime` 은 문자열 `"0"` 이 아니라 숫자 `0` 또는 `1` 이다
- 시각까지 넣으면 `is_datetime` 을 `1` 로 하고 start 에 `YYYY-MM-DDTHH:MM:00` 형태로 쓴다
- select 값은 위 표의 문구와 한 글자도 다르지 않게 쓴다. 없는 선택지를 쓰면 새 옵션이 생겨 뷰 필터에서 빠진다
- 마크다운 문법이 확실하지 않으면 추측하지 말고 노션 커넥터가 제공하는 마크다운 규격 문서를 먼저 읽는다
- 스크린샷 이미지는 노션에 올리지 않는다(`reference/safety.md`)
