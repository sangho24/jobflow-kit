# /jobflow:remind

마감을 놓치는 것이 지원 과정에서 가장 큰 손실이다. 이 스킬은 '지원 전' 건의 마감을 점검해 알려 준다.

## 시작 점검

1. `${user_config.workspace_dir}/config.yaml` 이 있는지 본다. 없으면 `/jobflow:setup` 을 먼저 돌리라고 안내하고 멈춘다.
2. config 에서 `notion.jobs_ds`, `remind.stages` 를 읽는다. `notion.jobs_ds` 가 비어 있으면 setup 이 덜 끝난 것이니 안내하고 멈춘다.
3. 노션 커넥터 도구가 보이는지 확인한다. 안 보이면 ToolSearch 로 `notion` 을 찾아보고, 그래도 없으면 claude.ai 설정에서 커넥터를 켜라고 안내하고 멈춘다. 확인법은 `${CLAUDE_PLUGIN_ROOT}/reference/connectors.md` 를 따른다.
4. 메일 발송 가능 여부를 정한다. `${user_config.notify_email}` 이 비어 있거나 Gmail 커넥터가 없으면(ToolSearch 로 `gmail` 확인) 메일은 보내지 않고 세션 안에서만 보고한다. 이 경우 그 사실을 한 줄로 알린다.

## 절차

### 1. 마감 임박 건 조회

노션 커넥터의 데이터 소스 SQL 조회 도구로 config 의 `notion.jobs_ds` 를 조회한다. 오늘 날짜는 실제 날짜로 바꿔 넣는다.

```sql
SELECT "기업명", "직무", "date:마감일:start" AS 마감, "마감 유형", "지원 페이지", "비고", url
FROM "<notion.jobs_ds 값>"
WHERE "진행 상태" = '지원 전'
  AND "date:마감일:start" IS NOT NULL
  AND date("date:마감일:start") >= date('<오늘 YYYY-MM-DD>')
ORDER BY date("date:마감일:start") ASC
```

날짜 컬럼은 `date:마감일:start` 확장 컬럼으로만 접근된다. `마감 유형` 이 `상시` 인 건은 임박 등급에서 제외하고 "상시 채용" 으로 따로 한 줄 묶는다.

### 2. 마감일이 비어 있는 '지원 전' 건 조회

가장 위험한 구간이다. 마감일이 없으면 알림이 울리지 않은 채 마감된다.

```sql
SELECT "기업명", "직무", "마감 유형", "지원 페이지", "비고", url
FROM "<notion.jobs_ds 값>"
WHERE "진행 상태" = '지원 전'
  AND "date:마감일:start" IS NULL
  AND ("마감 유형" IS NULL OR "마감 유형" != '상시')
  AND ("비고" IS NULL OR "비고" NOT LIKE '❌%')
```

결과는 "마감일 확인 필요" 로 따로 경고한다. 다음 두 종류는 마감일이 없는 것이 정상이므로 경고에서 제외한다.

- `마감 유형` 이 `상시` 인 행
- 비고 첫 줄이 `❌` 로 시작하는 자격 미달 확정 행(달력에서 빼려고 마감일을 일부러 비운다)

SQL 의 `LIKE` 가 줄 단위를 구분하지 못하거나 조건이 먹지 않으면 조회 결과를 받은 뒤 비고 첫 줄이 `❌` 인 행을 직접 걸러낸다.

### 3. 마감이 지난 '지원 전' 건 조회

```sql
SELECT "기업명", "직무", "date:마감일:start" AS 마감, "마감 유형", "지원 페이지", "비고", url
FROM "<notion.jobs_ds 값>"
WHERE "진행 상태" = '지원 전'
  AND "date:마감일:start" IS NOT NULL
  AND date("date:마감일:start") < date('<오늘 YYYY-MM-DD>')
ORDER BY date("date:마감일:start") DESC
```

이 목록은 알림 등급에 넣지 않고 "마감 지남, 확인 필요" 로 따로 묶는다. 처리는 7단계(상태 정리)에서 사용자에게 묻는다.

### 4. 등급 매기기

남은 일수는 마감일에서 오늘을 뺀 값이다. config 의 `remind.stages`(기본 `[7, 3, 1, 0]`)는 구간 경계다. 정확히 그날에만 울리는 방식이 아니다(수동 실행이라 하루를 건너뛸 수 있다). 기본값 기준은 다음과 같다.

- 남은 일수 0(오늘 마감): 🚨 오늘
- 1 이하: 🚨 즉시 판단
- 3 이하: ⚠️
- 7 이하: 알림
- 그보다 멀면: 목록에만 올린다

stages 를 바꾸면 경계가 그대로 따라 바뀐다. 예를 들어 `[14, 5, 2, 0]` 이면 0 = 🚨 오늘, 2 이하 = 🚨, 5 이하 = ⚠️, 14 이하 = 알림이다. 가장 큰 값보다 먼 건은 메일 없이 목록 보고만 한다.

### 5. 중복 확인

메일을 보내기 전에, 메일 발송이 가능하면 Gmail 커넥터의 검색 도구로 오늘 보낸 `[JobFlow]` 제목의 메일이 있는지 찾는다. 오늘 이미 같은 내용을 보냈다면 보내지 않고 세션 안에서만 보고한다. 같은 날 같은 알림을 두 번 보내지 않는다.

### 6. 알림 전달

알릴 건이 있고 메일 발송이 가능하면 Gmail 커넥터의 발송 도구로 `${user_config.notify_email}` 에 보낸다.

- 제목: `[JobFlow] <가장 급한 건> - 지원 전 N건 마감 알림`
- 본문:
  - 등급별 목록: 기업명, 직무, 마감 일시, 원본 지원 페이지 URL, 노션 행 링크
  - 마감일 확인 필요 건
  - 프로필에 미해결 항목이 있으면 함께 적는다. `${user_config.workspace_dir}/profile/master.yaml` 이 있을 때 값이 비어 있는 필수 항목이 있으면 그 항목 이름만 나열한다(값 자체는 메일에 넣지 않는다)
  - 증빙서류 유효기간 경고가 있으면 함께 적는다. 프로필에 서류 발급일 또는 유효기간 정보가 있고 곧 만료되거나 이미 만료됐으면(발급 후 3개월 기준 요구가 흔하다) 해당 서류와 만료 시점을 적는다

메일이 불가능하면 같은 내용을 세션 안에서 같은 구성으로 보고한다. 알릴 건이 하나도 없으면 "임박한 마감 없음" 이라고만 보고하고 메일은 보내지 않는다.

### 7. 상태 정리

3단계에서 모은 마감 지난 '지원 전' 건은 '공고마감' 으로 자동 변경하지 않는다. 지원하고 상태만 안 바꿨을 수 있다. 목록을 보여 주고 건별로 "지원했는지, 마감으로 닫을지" 를 사용자에게 묻는다. 답을 받은 건만 노션에서 갱신한다.

## 매일 자동으로 돌리려면

이 스킬은 호출될 때만 점검한다. 매일 받고 싶다면 Claude Code 의 예약 실행 기능으로 `/jobflow:remind` 를 등록하거나, 아침에 `/jobflow:remind` 를 한 번 실행하면 된다.

## 금지

- 같은 날 같은 알림을 두 번 보내지 않는다.
- 마감 지난 '지원 전' 건을 묻지 않고 '공고마감' 으로 바꾸지 않는다.
- 메일 본문에 프로필의 개인 값(연락처, 주소, 번호 등)을 넣지 않는다. 항목 이름만 쓴다.
- 메일 본문과 세션 보고에 민감 값(주민번호, 주소, 전화 등)을 넣지 않는다. 필요하면 `(입력함)` 만 적는다.
- 마감일을 추측해 노션에 채우지 않는다. 비어 있으면 확인이 필요하다고만 알린다.
