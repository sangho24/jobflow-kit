# 폼 자동입력 일반 지식

지원서 폼을 브라우저로 채울 때 반복해서 만나는 함정과 요령이다. 1인 실측에서 나온 것이라 사이트 개편 시 달라질 수 있다.

## 1. 선택 UI 필드에는 텍스트를 넣지 않는다

검색 버튼이나 드롭다운으로 고르는 필드에 스크립트로 글자만 넣으면, 화면에는 값이 보여도 서버로 갈 코드값은 비어 있다. 제출하면 학교, 전공 같은 항목이 빈 값으로 나가거나 검증 오류가 난다. 증상은 연동 필드가 열리지 않는 것으로 먼저 드러난다(학교를 글자로 넣었더니 졸업구분 select 의 옵션이 로드되지 않는 식). 주소도 같은 이유로 저장 시 값이 날아간 적이 있다.

다음 중 하나라도 해당하면 값을 넣지 말고 사용자에게 넘긴다.

1. `readonly` 이다
2. 옆에 "검색", "찾기" 버튼이 있다
3. 선택하면 다른 select 의 옵션이 채워지는 연동 구조다

이미 잘못 넣었으면 **비운 뒤** 넘긴다. 글자가 남아 있으면 사용자가 입력된 줄 알고 지나친다.

직접 입력해도 되는 것은 이름, 날짜, 평점, 전화번호 같은 자유 입력 필드다. select 는 옵션 목록에서 정확히 일치하는 항목을 골라 설정한다. 옵션이 빈 값 하나뿐이면 아직 로드 전이므로 건드리지 않는다.

## 2. 임시저장이 없는 ATS

Greenhouse 계열 폼과 Lever 는 저장 버튼이 없고 제출 버튼 하나뿐이다. 페이지를 벗어나거나 같은 탭에서 다른 URL 로 이동하면 입력이 전부 날아가고, 파일 업로드도 다시 해야 한다. 실제로 한 건을 다 채운 뒤 같은 탭에서 다른 회사로 이동해 통째로 날린 일이 있다.

- 작업 전에 폼에 저장 수단이 있는지 먼저 본다
- 없으면 사람이 바로 제출할 수 있을 때만 채운다. 아니면 기입안만 노션에 적는다
- 두 건 이상을 연달아 다루면 건마다 새 탭을 연다(`browser_tabs` 의 새 탭 동작)
- 반대로 Greeting 은 임시저장이 있다(90일 보관 사례), 인크루트 계열도 임시저장이 있다

Greenhouse 는 공개 Job Board API 로 폼 구조(질문 라벨, 필수 여부, 유형)를 브라우저 없이 읽을 수 있는 경우가 있다. 다만 일부 회사는 자체 폼을 얹어 API 가 막혀 있다. 사이트가 헤드리스 브라우저에 봇 점검을 띄우면 우회하지 말고 사람에게 넘긴다.

## 3. 인크루트 계열 폼의 함정

인크루트 기반 ATS(`*.incruit.com/apply/` 형태)에서 확인한 것이다. 상세는 [adapters/incruit.yaml](adapters/incruit.yaml).

1. 증명사진, 첨부서류 팝업을 닫으면 본문 폼이 다시 로드되어 입력이 전부 초기화된다. 그래서 순서를 **사진 -> 첨부 -> 나머지 입력 -> 즉시 임시저장**으로 잡는다.
2. 날짜 칸은 jQuery datepicker 이고 형식이 `yy-mm-dd` 라 일자까지 필요하다. 월까지만 넣으면 저장 시 오류로 거부된다. 값을 넣을 때는 위젯의 `setDate` 로 넣어야 내부 상태까지 맞는다.
3. 비밀번호에 특수문자를 넣으면 서버가 일부를 잘라 저장하는 경우가 있다. 새 계정을 만들 때는 발급 완료 화면의 값을 확인한다.
4. 임시저장 버튼이 부르는 함수가 플래그만 비우고 실제 전송은 별도의 `submit` 이 하는 구조다. 함수만 호출하면 저장되지 않으니 폼 submit 까지 해야 한다.
5. select 를 바꿀 때마다 `alert` 가 떠서 자동입력이 끊긴다. `window.alert = () => {}` 로 잠시 무력화한다.
6. 작업 전에 사람에게 "내가 만질 칸"을 먼저 알린다.

## 4. 브라우저 서버 두 가지

| 모드 | 장점 | 한계 |
|---|---|---|
| 별도 창 서버 (플러그인이 묶은 Playwright) | 파일 첨부가 된다. 프로파일이 영속되면 로그인 세션이 남는다 | 사이트마다 처음 한 번은 로그인해야 한다 |
| 내 크롬 탭에 붙는 확장 모드 (`--extension`, Playwright MCP Bridge 확장 필요) | 사용자가 이미 로그인, 본인인증한 탭을 그대로 이어받는다 | 파일 첨부가 막힌다. 아래 참고 |

- 확장은 **한 번에 서버 하나만** 붙는다. 다른 세션이 자기 서버를 띄우면 연결을 뺏기고, 연결이 새 빈 탭으로 바뀐다. 토큰을 환경 변수로 미리 넣어 두면 승인 창 없이 조용히 뺏겨서 눈치채기 어렵다. 서버가 여러 개 떠 있는지는 `ps` 로 `--extension` 프로세스를 세어 본다. 정리는 사용자 승인을 받고, 남의 세션 프로세스만 종료한다.
- 확장 모드에서 `browser_file_upload` 는 `DOM.setFileInputFiles: Not allowed` 로 실패한다. 권한 한계라 재시도해도 같다. 파일 첨부는 사람에게 넘기거나 별도 창 서버로 작업한다. 파일 선택창이 열려 있으면 `browser_file_upload` 를 경로 없이 호출해 닫는다.
- 별도 창 서버로 첨부할 때는 업로드 버튼을 클릭해 선택창을 연 뒤 `browser_file_upload` 에 절대경로를 준다. 서버가 허용한 폴더 밖의 파일은 올라가지 않으므로, 작업 폴더 안으로 복사한 뒤 올린다.
- **로그인 토큰을 탭의 `sessionStorage` 에 두는 사이트**는 새 탭이나 연결 재설정 때 로그아웃된다. 연결이 리셋될 때마다 다시 로그인해야 하니, 경쟁 서버부터 정리하고 로그인 직후에 한 번에 몰아서 작업한다. 사이트가 느릴 때 `goto`/`reload` 를 하면 토큰 갱신이 실패해 세션이 풀린 적이 있다. 로그인 뒤에는 화면 안 메뉴만 클릭해서 이동한다.

## 5. 날짜 입력 요령

- 년/월/일이 분리된 세그먼트(spinbutton) 위젯은 `fill` 이나 연속 타이핑이 먹지 않는다. 첫 세그먼트를 클릭한 뒤 `browser_press_key` 로 한 자리씩 누르면 자동으로 다음 칸으로 넘어간다. 숨은 input 에 `YYYY-MM-DD` 로 잡혔는지 확인한다.
- "재직 중" 같은 체크박스가 필드를 다시 그리면 이미 넣은 날짜가 지워진다. 체크를 먼저 하고 날짜를 넣는다.
- 마스크가 걸린 입력은 점(.) 을 한 글자씩 치면 마스크가 깨진다. 한 번에 `fill` 하고 Tab 으로 blur 해야 검증이 갱신되는 곳이 있다.
- 읽기 전용 달력은 달력 UI 를 클릭해서만 들어간다. 범위(시작/종료) 달력은 종료일을 고르면 시작일이 덮어써지는 경우가 있으니 마지막에 시작일을 다시 읽어 검증한다.
- 형식은 사이트마다 `YYYY.MM`, `YYYY.MM.DD`, `YYYY/MM/DD`, `yy-mm-dd` 로 갈린다. 형식이 틀리면 조용히 오늘 날짜로 덮어쓰는 곳도 있다. 입력 후 값을 다시 읽는다.

## 6. 그 밖의 반복되는 함정

- **기본값 함정**: select 가 첫 옵션을 선택한 채 시작한다. SKILL.md 의 전수 확인(verify)을 반드시 한다.
- **React 제어 컴포넌트**: 프로그램으로 `value` 만 바꾸면 상태에 반영되지 않는다. 입력 도구(`browser_fill_form`, `browser_type`)를 쓰거나, 네이티브 setter 후 `input`, `change`, `blur` 이벤트를 순서대로 발생시킨다. 이벤트를 덜 쏘면 화면에는 값이 보이는데 임시저장 후 빈칸이 되는 일이 있다.
- **같은 이름의 hidden 버튼**: 모바일/데스크톱 두 벌이 DOM 에 있고 첫 번째가 숨겨진 경우가 많다. role 이나 스냅샷 ref 로 잡는다. 닫힌 모달의 버튼이 DOM 에 남아 잘못 눌리기도 하니, 보이는 마지막 `[role=dialog]` 안에서만 찾는다.
- **팝업이 클릭을 가로막음**: 달력이 열린 채면 저장 버튼 클릭이 막힌다. 저장 전에 팝업을 닫는다.
- **주소 위젯**: 우편번호 검색 팝업에서 결과 항목을 클릭하지 않고 확인을 누르면 상세주소만 들어가고 나머지가 빈다. 주소는 사용자에게 넘기는 편이 안전하다.
- **만점 기준과 환산**: 학점은 4.5 / 4.3 / 100점 환산으로 요구가 갈린다. 폼이 만점 기준을 고르게 해 주면 마스터 프로필에 있는 값 중 정확히 일치하는 쪽을 고른다.
- **세션 타임아웃**: 30분에서 2시간까지 사이트마다 다르다. 만료 전에 임시저장하고, 이탈 시 `beforeunload` 다이얼로그가 뜨면 `browser_handle_dialog` 로 처리한다.
- **빈 카드 부작용**: 모달에 입력하는 방식의 폼에서 잘못 저장하면 빈 학력, 자격 카드가 생기고 임시저장은 통과한다. 저장 뒤 전체 화면을 확인해 빈 카드를 찾는다.
- **공고 첨부 가이드를 먼저 읽는다**: 폼에 입력란이 있다고 필수가 아니다. 공고에 첨부된 지원서 입력 가이드에 "선택 사항"이라고 적힌 항목이 있다.

## 7. robots.txt 와의 관계

robots.txt 의 Disallow 는 공고 정보를 긁어 오는 수집(intake)에 적용되는 규칙이다. 사용자가 자기 계정으로 로그인해 자기 지원서를 작성하는 대행은 크롤링이 아니므로 해당하지 않는다. 지원서 작성 요청을 robots 를 근거로 거절하지 않는다. 다만 User-Agent 위조 같은 봇 차단 우회는 여전히 하지 않는다.
