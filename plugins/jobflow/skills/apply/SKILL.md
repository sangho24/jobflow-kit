# /jobflow:apply

조사(survey) -> 입력(fill) -> 공백 분류(gap) -> 전수 확인(verify) -> 보고(report) 순서로 진행한다.

## 절대 규칙

정본은 [${CLAUDE_PLUGIN_ROOT}/reference/safety.md](${CLAUDE_PLUGIN_ROOT}/reference/safety.md) 다. 아래는 이 스킬에서 특히 중요한 요약이다.

1. **제출 버튼을 누르지 않는다.** 임시저장까지만 한다. 잘못 낸 지원서는 되돌릴 수 없다. 사용자 자신의 크롬 탭에서도 마찬가지다.
2. **값을 지어내지 않는다.** `${user_config.workspace_dir}/profile/master.yaml` 에 없는 값은 결정 필요 큐로 보낸다.
3. **본인인증(PASS·휴대폰), 캡차, 2FA 는 사용자에게 넘긴다.** 우회하지 않는다.
4. **계정을 자동으로 만들지 않는다.** 가입이 필요하면 노션 `계정 상태`를 `생성필요`로 바꾸고 사용자에게 알린다.

## 시작 점검

1. `${user_config.workspace_dir}/config.yaml` 이 있는지 본다. 없으면 `/jobflow:setup` 을 먼저 실행하라고 안내하고 멈춘다.
2. `${user_config.workspace_dir}/profile/master.yaml` 을 읽는다. 없거나 비어 있으면 멈추고 setup 을 안내한다. 핵심 칸(이름, 연락처, 학력)이 빈 채라면 먼저 경고한다.
3. 노션 커넥터가 있는지 확인한다. 도구가 안 보이면 ToolSearch 로 `notion` 을 찾아보고, 그래도 없으면 claude.ai 설정에서 커넥터를 켜라고 안내하고 멈춘다. 확인법은 [${CLAUDE_PLUGIN_ROOT}/reference/connectors.md](${CLAUDE_PLUGIN_ROOT}/reference/connectors.md).
4. 브라우저 도구를 확인한다. 플러그인이 묶은 Playwright 서버(`plugin:jobflow:playwright`)를 기본으로 쓰고, 사용자가 따로 쓰는 Playwright 서버(예: 자기 크롬 탭에 붙는 확장 모드)가 있으면 그것을 써도 된다. 도구가 없으면 중단하고 알린다. 두 모드의 차이(파일 첨부 가능 여부, 로그인 세션 유지 여부)는 [form-knowledge.md](form-knowledge.md) 를 본다.

## 자격증명 취급

`config.yaml` 의 `credentials.backend` 를 따른다.

- **`keychain` (macOS)**: 서비스명 `<prefix>-<ats>` 로 조회한다. `prefix` 는 config 의 `credentials.prefix`. 같은 ATS 라도 계정이 회사별로 갈리는 곳은 `<prefix>-<ats>-<기업>` 으로 나눈다.
  ```bash
  security find-generic-password -s <prefix>-<ats> -w                     # 조회
  ```
  저장이 필요하면 사용자가 **터미널에서 직접** 아래를 실행해 프롬프트에 비밀번호를 입력하게 안내한다. 비밀번호를 명령줄 인자로 넘기지 않는다(셸 기록과 프로세스 목록에 남는다).
  ```bash
  security add-generic-password -s <prefix>-<ats> -a <계정 이메일> -U -w   # 값 없이 -w 를 맨 끝에 주면 프롬프트로 묻는다
  ```
- **`ask` 또는 그 밖의 값**: 매번 사용자에게 묻는다. 어디에도 저장하지 않는다.

공통 규칙:

- 비밀번호를 파일, 노션, 로그, 메일 본문에 쓰지 않는다. 산출물에는 "Keychain `<서비스명>` 참조"처럼 출처만 남긴다.
- **비밀번호가 틀리면 재시도하지 않는다.** 계정 잠금 위험이 실익보다 크다. 사용자에게 알리고 멈춘다.
- 사이트에 따라 비밀번호의 특수문자가 일부 잘려 저장되기도 한다. 새 계정의 비밀번호는 사이트가 받아들이는 문자 범위를 안내문에서 확인한 뒤 정한다.
- 이메일 인증코드: 기본은 멈추고 사용자에게 코드를 받는다. 사용자가 그 세션에서 "메일에서 찾아서 넣어줘"처럼 명시적으로 요청한 경우에만 Gmail 커넥터로 그 코드 하나를 읽어 입력한다(다른 메일은 열지 않는다). PASS·휴대폰 본인인증, 캡차, 2단계 인증 앱은 예외 없이 사람 몫이다.
- 자격증명이 필요하거나 틀렸을 때 사용자에게 직접 묻는다. `${user_config.notify_email}` 이 설정돼 있고 Gmail 커넥터가 있을 때만 같은 내용을 메일로도 알린다(제목에 기업명과 한 줄 상황, 본문에 어디까지 갔고 무엇에 막혔고 마감까지 얼마 남았는지. 비밀번호는 절대 쓰지 않는다).

## 절차

### 0. 임시저장이 있는지 먼저 본다

저장 수단이 없는 ATS 가 있다(Greenhouse 계열, Lever 등). 채워 둔 뒤 페이지를 벗어나면 입력이 전부 사라진다.

| 저장 수단 | 전략 |
|---|---|
| 임시저장 있음 | 평소대로 채우고 단계마다 저장한다. 제출은 사람이 나중에 검토하고 한다 |
| 임시저장 없음 (Greenhouse, Lever 등) | 기본은 **채우지 않는다.** 폼 구조를 캡처하고 필드별 기입안만 노션 `## 4. 입력 내역`에 보고한다. 사용자가 원하면 채워 두고 **사용자가 직접 제출**한다(제출은 항상 사람) |

사용자가 원해서 임시저장 없는 폼을 채우는 경우에도, 두 건 이상이면 건마다 탭을 나눈다. 같은 탭에서 다른 URL 로 이동하면 앞 건이 날아간다.

### 1. survey: 폼 조사

1. 노션 행에서 `지원 페이지` URL 과 `ATS` 를 읽는다.
2. `adapters/<ats>.yaml` 을 읽는다. 없으면 폼을 조사해 새로 만든다. 회사 전용 어댑터 예시는 `adapters/examples/` 에 있다. 어댑터는 1인 실측이라 사이트가 바뀌었을 수 있으니, 어댑터와 실제 화면이 다르면 화면을 믿는다.
3. 브라우저로 접속한다.
   - 로그인이 필요하면 브라우저 프로파일에 세션이 있는지 본다. 없으면 자격증명 절차를 따르거나 사용자에게 직접 로그인을 부탁하고 기다린다.
   - 계정이 없으면 노션 `계정 상태`를 `생성필요`로 바꾸고 알린다. 자동 가입 금지.
4. 단계마다 **접근성 스냅샷**을 받는다. 스크린샷은 사람 확인용 보조다. 스냅샷의 라벨이 필드 식별자다. 셀렉터 하드코딩보다 라벨 매칭을 먼저 한다.
5. 결과를 `${user_config.workspace_dir}/runs/<기업명>/fields.json` 으로 저장한다.

### 2. fill: 자동 입력

1. 필드 라벨을 [field-registry.yaml](field-registry.yaml) 의 `label_variants` 와 맞춘다.
2. `maps_to` 가 있고 `confidence: high` 이면 `master.yaml` 값을 넣는다. 어학은 `languages[test=OPIc].level` 처럼 목록에서 시험명으로 항목을 고른다.
3. 넣은 값을 전부 기록한다(항목 / 입력값 / 출처 경로).
4. **입력 방식의 제한을 지킨다.** 읽기 전용이거나 검색 버튼이 붙었거나 선택하면 다른 칸이 연동되는 필드에는 텍스트를 주입하지 않고 사용자에게 넘긴다. 이미 넣었으면 비운다. 상세는 [form-knowledge.md](form-knowledge.md).
5. 형식이 ATS 마다 다르다. 학점 만점 기준(4.5 / 4.3 / 100점 환산), 날짜 형식(연월 / 연월일, 구분자), 사진 비율은 어댑터를 따른다. 예를 들어 100점 환산을 요구하는 폼에는 `education.university[0].gpa_100` 값을 쓰고, 값이 없으면 지어내지 말고 결정 필요로 보낸다.
6. 각 단계 끝에서 임시저장하고 다음으로 넘어간다. 저장 성공은 화면 신호(토스트, 버튼 상태)와 새로고침 후 값 유지로 확인한다.

### 3. gap: 결정 필요 분류

매칭에 실패했거나 `confidence: low` 인 필드를 세 갈래로 나눈다.

- **신규 필드**: 레지스트리에 없음. 사용자가 정하면 `field-registry.yaml` 에 추가한다(학습).
- **공고별 상이**: 지원 분야, 희망 근무지, 희망 연봉처럼 공고마다 다른 것. 항상 사용자가 정한다.
- **자기소개서**: 문장은 사용자가 쓴다. `${user_config.workspace_dir}/profile/experiences/` 의 경험 카드에서 어울리는 소재만 제시한다.

### 4. verify: 제출될 값을 전수 확인

**내가 설정한 필드만 확인하면 안 된다.** 국내 ATS 의 select 는 빈 값이 아니라 첫 옵션이 선택된 상태로 시작하는 경우가 많아, 건드리지 않은 필드가 조용히 틀린 값으로 나간다.

사고 사례(익명화): 어느 대기업 ATS 에서 "최종 학력"만 학사로 설정하고, 이름이 비슷한 "학업 과정" select 를 방치했더니 기본값인 전문학사로 제출될 뻔했다. 사용자가 육안으로 발견했다.

1. 폼에서 필수 표시(`*`)가 붙은 **모든** 필드를 열거한다. 내가 채운 것만이 아니다.
2. 각 필드의 현재 값을 읽는다. select 는 `selectedOptions[0].text` 로 읽는다.
3. 마스터 프로필과 대조해 **표로** 사람에게 보고한다(필드 / 현재 값 / 프로필 기준 값 / 일치 여부). 값이 없거나 의심스러우면 명시한다.
4. 이름이 비슷한 필드 쌍(`...Type` 과 `...LatestType` 같은)은 특히 따로 읽는다.

### 5. report: 노션 기록

해당 공고 행 본문에 쓴다. 노션 커넥터의 페이지 수정 도구를 쓴다.

- `## 4. 입력 내역`: 표(항목 / 입력값 / 출처 경로). 임시저장 없는 ATS 는 "기입안"으로 적는다. master.yaml 의 민감 필드(템플릿의 `meta.sensitive` 목록: 주민번호, 주소, 전화 등)는 값 대신 `(입력함)` 만 적는다. 노션과 보고서에 민감 값을 쓰지 않는다.
- `## 5. 결정 필요`: 체크박스 목록. 사람이 넘겨받아야 할 칸(검색형 필드, 파일 첨부, 본인인증), 공고별 상이 항목, 자기소개서 소재.
- 속성 `자동화 상태` 갱신: 입력을 마치면 `입력완료`, 사람 검토를 기다리면 `검토대기`, 막히면 `차단됨`(비고 첫 줄에 사유). 제출은 사람이 하고 나서 `진행 상태`를 바꾼다.

`${user_config.notify_email}` 이 설정돼 있고 Gmail 커넥터가 있으면, 막힌 지점이나 검토 대기 사실을 그 주소로 메일 보고해도 된다. 둘 중 하나라도 없으면 세션 안에서만 보고한다.

### 6. 사후

- 새로 배운 필드를 `field-registry.yaml` 에 반영한다. `seen_in` 에는 ATS 이름만 적고 기업명은 넣지 않는다.
- 어댑터의 `field_hints` 를 갱신한다. 새로 확인한 함정은 확인일과 함께 적는다.

## 금지

- 제출·최종제출 버튼 클릭, 결제, 약관 일괄 동의 후 제출.
- 값 지어내기, 본인인증·캡차 우회, 자동 회원가입.
- 비밀번호를 파일, 노션, 로그, 메일에 남기기. 틀린 비밀번호 재시도.
- 선택 UI 필드에 텍스트 주입.
- 봇 차단 우회(User-Agent 위조 등). robots.txt 는 공고 수집(intake)에 적용되는 규칙이고, 본인 계정으로 본인 지원서를 채우는 것은 해당하지 않는다. 다만 사이트가 봇 점검(Turnstile 등)을 띄우면 우회하지 말고 사람에게 넘긴다.
