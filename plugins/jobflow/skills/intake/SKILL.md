# /jobflow:intake

공고를 노션 트래커에 등록하는 단계다. 핵심은 확인하지 못한 공고를 지원 대상으로 올리지 않는 것이다.

## 시작 점검

1. `${user_config.workspace_dir}/config.yaml` 이 있는지 본다. 없으면 `/jobflow:setup` 을 먼저 돌리라고 안내하고 멈춘다
2. 노션 커넥터를 확인한다. 도구가 안 보이면 ToolSearch 로 `notion` 을 찾고, 그래도 없으면 `${CLAUDE_PLUGIN_ROOT}/reference/connectors.md` 대로 안내하고 멈춘다
3. config 에서 읽을 값: `notion.jobs_ds`(채용 일정), `notion.scrap_ds`(취업 스크랩), `eligibility`, `targets`, `filters.salary_floor`, `intake.default_target_days`. `eligibility` 가 비어 있거나 기본 양식 그대로면 판정할 기준이 없으니, `/jobflow:setup` 의 프로필 단계를 먼저 돌리라고 안내하고 멈춘다
4. `${user_config.workspace_dir}/collect-target.md` 를 읽는다(우선순위와 추적 회사 표에 쓴다)
5. 노션 속성 이름과 선택지는 `${CLAUDE_PLUGIN_ROOT}/reference/notion-schema.md` 가 정본이다. 다른 이름을 지어내지 않는다
6. 안전 원칙은 `${CLAUDE_PLUGIN_ROOT}/reference/safety.md` 를 따른다

필수 참고: 자격 판정은 `${CLAUDE_PLUGIN_ROOT}/reference/intake-gate.md`(판정축 6개, 상태 게이트, 스크린샷 증거력)가 정본이다. 아래는 요약이다.

## 절차

### 1. 입력 판별

| 입력 | 다음 |
|---|---|
| 이미지, 스크린샷(첨부 또는 파일 경로) | 1-A 로 |
| URL | 3단계로 |
| 기업명 + 직무만 | 3단계로 (검색해서 원본을 찾는다) |

이미지가 첨부되면 사용자가 말을 덧붙이지 않아도 이 스킬을 시작한다. "이거 봐줘" 한마디에 공고 화면이 붙어 있으면 그게 intake 요청이다.

### 1-A. 스크린샷 경로

봇이 열 수 없는 소스(로그인이 필요한 학교 취업지원 사이트, 일부 국내 취업 포털 등)는 스크린샷으로만 들어온다. 화면 유형 분류, 주소창 도메인 판독, 이미지 준비, 부족분 요청, 보관 규칙은 [screenshot.md](screenshot.md) 를 따른다. 요점만 적으면 다음과 같다.

- 판독 순서는 본문이 아니라 주소창이 먼저다. 도메인이 증거력을 정한다
- 이미지는 직접 보고 읽는다. 긴 세로 이미지는 잘라서 본다
- 원본은 `${user_config.workspace_dir}/snapshots/YYYY-MM-DD-<기업슬러그>.png` 로 보관하고, 노션에는 기본값으로 올리지 않는다

### 2. 분류

| 분류 | 기준 | 목적지 |
|---|---|---|
| 채용공고 | 기업명 + 직무가 식별됨 | 채용 일정 DB (`notion.jobs_ds`) |
| 부대자료 | 공모전, 해커톤, 특강, 합격자료 | 취업 스크랩 DB (`notion.scrap_ds`) |
| 버림 | 학사행정 공지, 광고성 링크 | 등록하지 않음 |

### 3. 원본 공고 URL 복원

집계 사이트 링크가 많이 들어온다. 집계 요약으로는 판정하지 않고 원본 ATS 를 찾는다. 방법과 주의는 [sources.md](sources.md) 를 따른다. 요점은 다음과 같다.

1. Playwright 로 집계 페이지를 열어 본문 하단 "지원하러 가기" 링크에서 원본 ATS URL 을 복원한다. 검색으로 추측하는 것보다 정확하다
2. Playwright 가 없는 세션에서만 WebSearch 로 기업명 + 직무를 검색한다
3. 노션 `지원 페이지` 에는 집계 링크가 아니라 원본 URL 을 넣는다

샌드박스 환경에서는 국내 채용 사이트에 curl 을 날리면 타임아웃이 나는 일이 있다. 사이트가 죽은 것이 아닐 수 있으니, "열리지 않는다"고 결론 내리기 전에 Playwright 로 다시 확인한다.

봇 차단을 우회하지 않는다. User-Agent 위조, 로그인 우회, robots 무시는 하지 않는다.

차단되어 원문을 열지 못한 공고는 그 자리에서 `🔴 미확인` 행을 먼저 만들고(아래 4단계의 미확인 처리), 사용자에게 스크린샷을 요청한다. 나중으로 미루면 누락된다. 화면이나 대화에 보이는 URL 을 그대로 적고, 비고에 `📸 스크린샷 확인 - 봇 차단 소스` 를 남긴다. URL 이 없으면 목록 페이지 주소를 넣고 미확인으로 둔다.

### 4. 자격요건 검사: 통과 못 하면 지원 대상으로 올리지 않는다

직무명은 자격의 근거가 아니다. 근거가 될 수 있는 것은 공고 원문의 자격요건 문장뿐이고, 그 문장을 비고에 그대로 인용한다.

#### 판정축 6개

내 값은 config.yaml 의 `eligibility` 에서 읽는다.

| 축 | 내 값 | 자주 걸리는 지점 |
|---|---|---|
| 경력 연차 | `eligibility.career` | "N년 이상", 경력기술서 필수, intermediate/mid-level, ATS 경력 필드 |
| 학위 | `eligibility.degree` | 석사 이상 한정 직무 |
| 졸업 연도 | `eligibility.graduation` | `final year students` 는 재학생 대상 |
| 전공 | `eligibility.majors` | 공학 한정, 상경 한정 |
| 어학 | `eligibility.languages` | 인정 시험을 자격요건 아래 별도 표로만 적는 곳이 있다 |
| 비자·근무지 | `eligibility.overseas_ok`, `needs_visa_sponsorship` | 근무지는 탈락 사유가 아니다. 스폰서십 여부로 판단 |

#### 스크린샷 증거력

사람이 원본 ATS 화면에서 찍은 스크린샷은 원문 근거로 인정한다. 조건 셋(원본 ATS 도메인, 문장이 잘리지 않음, 비고에 인용과 출처)을 모두 채워야 하고, 하나라도 빠지면 그 축만 `🔴 미확인` 이다. 축별로 따로 판정하며, "화면에 안 쓰여 있으니 제한이 없다"고 읽지 않는다. 세부는 intake-gate 규칙 6 을 따른다.

#### 상태 게이트

```
6개 축 중 하나라도 원문 확인 못 함
  -> 자동화 상태 = 미시작, 우선순위 = 비움
  -> 비고 첫 줄: "🔴 자격요건 미확인 - 지원 대상 아님. <못 본 축>"
6개 축 전부 원문 확인
  -> 자동화 상태 = 조사완료, 그때 우선순위 부여
```

`우선순위` 가 붙어 있다는 것은 원문 검증을 마쳤다는 뜻이다. 스크린샷으로 확인한 축도 같은 자격을 갖는다.

미달이 확정되면 비고 맨 앞에 `❌ 자격 미달 확정 - <원문 인용>` 을 적는다. 추론으로 미달 처리하지 않는다.

#### 우선순위와 연차 상한

- 우선순위는 `${user_config.workspace_dir}/collect-target.md` 의 기준과 config `targets.priority_map` 을 따른다. 1순위 직무(`targets.tier1_roles`)는 `priority_map.tier1`, 2순위는 `tier2`, 그 외는 `other` 값이다
- 원문의 연차 요건이 `targets.max_years_required` 보다 크면 노션에 등록하지 않는다. collect-target.md 의 추적 회사 표에 `회사 | 직무 | 근무지 | 요건 요지 | 확인일 | 출처` 열 그대로 한 줄을 추가한다(요건 요지에 원문 연차 문장, 출처에 원본 URL)

#### 우선순위 판정 순서

1. `targets.exclude` 에 해당하는 회사 유형이나 직무면 등록하지 않거나, 등록 전에 사용자에게 먼저 묻는다. 임의로 버리지 않는다
2. 직무가 `targets.tier1_roles` 키워드에 해당하면 `priority_map.tier1`
3. 아니고 `targets.tier2_roles` 키워드에 해당하면 `priority_map.tier2`
4. 둘 다 아니면 `priority_map.other`
5. 이 판정은 6축을 전부 원문으로 확인한 뒤에만 한다(상태 게이트)

#### 급여 기준

`filters.salary_floor`(만원 단위)가 null 이 아니고 공고에 급여가 적혀 있을 때만 비교한다. 기준에 못 미치면 비고에 원문 급여 문장을 인용해 알리고 등록 여부는 사용자 판단에 맡긴다. 자동 탈락 처리하지 않는다. 공고에 급여가 없으면 비고에 "급여 미명시"로 적는다. 추측해서 채우지 않는다.

#### 같은 회사라도 요건은 다르다

정규직과 인턴, New Grad 와 Internship 은 요건이 서로 다르다. 하나를 읽고 나머지를 추정하지 않는다. 자소서가 없거나 다른 서식으로 대체된 공고도 있으니, 문항이 있다고 가정하지 않는다.

집계 사이트의 제목과 요약으로 판정하지 않는다. 원본 ATS 를 못 열었으면 그 자체가 미확인이다.

### 5. 중복 판정

키는 기업명 + 직무다. 기업명만으로 판정하면 한 회사의 여러 공고가 뭉개진다. 기존 행에 직무가 비어 있으면 신규 생성 대신 갱신한다.

스크린샷은 같은 공고가 여러 장으로 온다. 같은 제목, 같은 도메인으로 이어지는 화면이면 3장을 보내도 1건이다. 반대로 목록 화면 한 장에 8건이 들어 있을 수도 있다. 장수와 건수는 무관하다.

### 6. 노션 쓰기

채용 일정 DB(`notion.jobs_ds`)에 행을 만든다. 속성 이름은 notion-schema.md 와 같게 쓴다.

`기업명`(title), `직무`, `모집 유형`, `진행 상태`=지원 전, `지원 페이지`, `마감일`, `마감 유형`, `ATS`, `계정 상태`, `자동화 상태`, `우선순위`, `비고`

`ATS` 판별(선택지는 notion-schema.md 기준):

| 주소 패턴 | ATS | 계정 상태 |
|---|---|---|
| `*.recruiter.co.kr` | recruiter.co.kr | 생성필요 |
| `gh_jid=` 또는 `greenhouse.io` | Greenhouse | 불필요 |
| `jobs.lever.co` | Lever | 불필요 |
| `*.myworkdayjobs.com` | Workday | 생성필요 |
| `*.greetinghr.com` (추정) | Greeting | 생성필요 |
| `*.careerlink.kr` 계열 (추정) | careerlink | 생성필요 |
| `*.incruit.com` 계열 (추정) | 인크루트 | 생성필요 |
| 기업 자체 채용 사이트, Oracle HCM 등 위 목록에 없는 시스템 | 자체구축 | 생성필요 |
| 원본을 못 열어 판별 불가 | 미확인 | 생성필요 |

`(추정)` 표시 패턴은 정확한 도메인을 확인하지 못한 값이다. 처음 만나면 원본 주소로 확인하고 맞춰 쓴다. 기존에 계정이 있으면 `보유` 로 바꾼다.

행 본문은 `## 1. 공고` ~ `## 5. 결정 필요` 구조를 따르고, §1 에 담당 업무, 지원 자격, 채용 일정, 비고를 채운다. 확인 못 한 값은 비워 두지 말고 "미확인"이라고 적어 나중에 구분되게 한다.

노션 쓰기에서 `is_datetime` 은 문자열이 아니라 숫자 0 또는 1 이다. `"1"` 은 400 에러가 난다.

### 7. 마감일은 반드시 채운다

비고에 적는 것으로는 안 된다. 노션 `달력` 뷰는 `마감일` 기준이라 날짜 없는 행을 아예 렌더링하지 않는다. 날짜 없이 등록하면 사용자 화면에서 그 행이 통째로 사라져 "추가가 안 됐다"고 보이고, 그대로 마감을 놓친다.

| 상황 | `마감일` | `마감 유형` | 비고 첫 문장 |
|---|---|---|---|
| 공식 마감일 있음 | 그 날짜(시각이 있으면 `is_datetime`) | 확정 | 평소대로 |
| 상시채용, rolling, "채용 시 마감" | 자체 목표일(언제까지 낼지 정한 날) | 상시 | `⚠️ 마감일은 자체 목표일 - 회사 공식 마감 아님(상시채용).` |
| 아직 못 찾음 | 조사 시점 + `intake.default_target_days` 일의 잠정 목표일 | 잠정 | `⚠️ 마감일 미확인 - 잠정 목표일. 원본 재확인 필요.` |

자체 목표일은 적합도와 "빠를수록 유리한가"로 순서를 매긴다. 선착순 성격(상시 채용 계약직 등)이면 가장 앞에 둔다.

유일한 예외: 자격 미달로 확정된 건은 마감일을 비운다. 달력에는 내가 실제로 낼 것만 떠야 의미가 있다. 비고 맨 앞에 `❌ 자격 미달 확정 - <원문 근거>` 를 적고 날짜는 비워 둔다. remind 의 "마감일 확인 필요" 경고는 이 행과 `마감 유형 = 상시` 행을 제외한다(정책은 [safety.md](${CLAUDE_PLUGIN_ROOT}/reference/safety.md) 와 규약 0절).

날짜가 없어도 `🎯 지원 대상` 뷰(진행 상태 = 지원 전)에는 보인다. 달력에서 안 보이면 거기를 확인한다.

### 8. 등록 후 보고

스크린샷 한 묶음을 처리했으면 건수와 상태를 한 번에 보고한다.

```
스크린샷 3장 -> 공고 5건
  ✅ 조사완료 2건: <기업/직무>
  🔴 미확인 2건: 어학 요건이 화면에서 잘림. 해당 부분 한 장 더 필요
  ❌ 미달 1건: "최소 3년 이상" (원문 인용)
```

미확인 건은 무엇이 빠졌는지 축 이름으로 말한다. "정보 부족"은 다음 행동이 나오지 않는다.

## 금지

- 봇 차단 우회(UA 위조, 로그인 우회 등)
- 스크린샷에 안 보이는 것을 추정해 채우는 것. 잘린 자격요건은 미확인이다
- 집계 사이트 화면을 원문 근거로 쓰는 것. 도메인을 먼저 본다
- 확인하지 못한 공고에 우선순위를 붙이는 것
- 마감일을 비워 두는 것(미달 확정 건 제외)
- 노션 `진행 중`, `지원 결과` 뷰에 중복 기록하는 것. 같은 데이터소스의 뷰다
- 개인정보를 노션에 올리는 것. 스크린샷은 기본값으로 올리지 않는다
