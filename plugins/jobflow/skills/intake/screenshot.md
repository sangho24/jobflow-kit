# 스크린샷 처리 상세

`/jobflow:intake` 1-A 단계의 상세 절차다. 증거력 규칙의 정본은 `${CLAUDE_PLUGIN_ROOT}/reference/intake-gate.md` 규칙 6 이다.

## 왜 따로 다루는가

로그인이 필요한 학교 취업지원 사이트, 주요 국내 취업 포털, 일부 대기업 채용 사이트, 블로그형 플랫폼은 봇이 열 수 없다. 이런 소스는 사람이 화면을 찍어 넘기는 경로가 아니면 파이프라인에 들어오지 않는다. 여기서 막히면 그 공고들은 영원히 누락된다.

## 1. 화면 종류부터 가른다

| 유형 | 화면에 보이는 것 | 다음 동작 |
|---|---|---|
| A. 대화 피드 | 말풍선, 긴 세로, 링크 여러 개(메신저, 문자, 디스코드) | 건별로 쪼갠 뒤 각각 3단계 |
| B. 공고 상세 | 제목 + 자격요건 본문 | 도메인 판정 후 4단계에서 증거로 쓸 수 있는지 결정 |
| C. 목록 화면 | 여러 행의 제목과 마감일(포털, 학교 사이트, 기업 채용홈) | 건별로 쪼갠다. 각 건은 아직 전부 미확인이다 |
| D. 지원 현황, 폼 | 내 지원 상태, 접수 완료 화면 | 신규 등록이 아니다. 기존 행의 `진행 상태` 를 갱신한다 |

한 장에 두 유형이 섞이면(목록 + 펼쳐진 상세) 상세 쪽만 B 로 다루고 나머지 행은 C 로 남긴다.

## 2. 주소창을 먼저 읽는다

판독 순서는 본문이 아니라 주소창(또는 앱 헤더)이 먼저다. 도메인이 증거력을 정한다.

| 화면 도메인 | 4단계에서 |
|---|---|
| 원본 ATS(기업 채용 사이트, 채용 솔루션 도메인, 학교 취업지원 사이트의 공고 상세) | 원문 근거로 인정 |
| 채용 정보 집계 사이트, 자소서 커뮤니티, 채용 포털 | 인정 안 함. 원본을 따로 연다 |
| 대화 앱 | 인정 안 함. 링크를 복원해 3단계로 |
| 주소창이 안 보임 | 미확인 취급. 주소창까지 포함해 다시 찍어 달라고 요청 |

모바일 앱 스크린샷에는 주소창이 없다. 앱 이름과 화면의 발행처 표기로 판단하고, 애매하면 미확인으로 둔다. 추측해서 인정 쪽으로 넘기지 않는다.

## 3. 이미지 준비

이미지는 직접 보고 읽는 것이 기본이다. 세로로 아주 긴 이미지(약 9000px 초과)는 한 번에 못 읽으니 4000px 단위로 잘라서 본다.

```bash
python3 -c "
from PIL import Image; im=Image.open('SRC.png'); w,h=im.size
for i in range((h+3999)//4000): im.crop((0,i*4000,w,min(h,(i+1)*4000))).save(f'part{i:02d}.png')"
```

PIL 이 없으면 `pip install pillow` 는 사용자 승인을 받은 뒤에만 실행한다. 설치하지 않아도 이미지를 직접 보는 기본 경로로 진행할 수 있고, 너무 길어 읽히지 않으면 사용자에게 화면을 나눠 찍어 달라고 한다.

별도 OCR 도구가 있어도 훑는 용도로만 쓴다. 판정에 인용할 문장은 반드시 이미지를 직접 보고 읽는다. OCR 은 줄과 열 정렬이 깨져서 "5년 이상" 같은 조건절을 엉뚱한 항목에 붙인다.

## 4. 부족하면 무엇이 부족한지 짚어서 요청한다

스크린샷 한 장으로 판정축 6개가 다 차는 경우는 드물다. 막히면 멈추지 말고 어디까지 스크롤해 달라고 구체적으로 요청한다.

> "자격요건 블록이 잘려 있습니다. `지원 자격` 항목 끝까지 스크롤해서 한 장 더 주세요. 주소창이 같이 나오면 그대로 근거로 쓸 수 있습니다."

요청하기 전에 채울 수 있는 축은 먼저 채운다. 기업명, 직무, 마감일이 이미 보이면 그건 확정하고 못 채운 축만 남긴다. 차단되어 원문을 못 연 공고는 요청과 동시에 `🔴 미확인` 행을 먼저 만든다.

## 5. 원본은 보관하되 노션에는 올리지 않는다

- 저장: `${user_config.workspace_dir}/snapshots/YYYY-MM-DD-<기업슬러그>.png`
- 노션 첨부는 기본값으로 하지 않는다. 대화 피드 스크린샷에는 제3자 이름, 프로필 사진, 업무 알림이 섞인다. 필요한 문장만 인용하고, 이미지를 올려야 할 이유가 생기면 그때 사용자가 판단한다
