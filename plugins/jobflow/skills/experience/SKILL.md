# /jobflow:experience

경험을 캐물어 `<workspace_dir>/profile/experiences/<슬러그>.md` 카드로 저장한다. 정리 방법과 카드 양식은 [method.md](method.md) 가 정본이다.

## 왜 필요한가

마스터 프로필에는 경력과 프로젝트가 한 줄짜리 사실로만 들어간다. 자소서에는 그것으로 부족하고, 무엇이 문제였고 내가 무엇을 판단했고 어떻게 됐는지가 필요하다. 그 층을 카드로 미리 만들어 두면 지원마다 처음부터 다시 쓰지 않는다.

## 시작 점검

1. `${user_config.workspace_dir}/config.yaml` 이 있는지 본다. 없으면 `/jobflow:setup` 을 먼저 돌리라고 안내하고 멈춘다.
2. `${user_config.workspace_dir}/profile/experiences/` 가 없으면 만든다. `_INDEX.md` 가 있으면 읽어 기존 카드와 주제 열을 파악한다.
3. [method.md](method.md) 를 읽는다.

## 절차

### 1. 대상 고르기

사용자가 말한 경험이 있으면 그것부터 한다. 없으면 `profile/master.yaml` 이 있을 때 경력, 프로젝트, 수상, 활동 항목을 훑어 후보를 제안하되, 후보는 그 파일에 적힌 것에서만 뽑는다. 우선순위는 지원하려는 직무나 문항과 겹치는 순서다(`/jobflow:fit` 결과가 있으면 참고). 한 번에 한 경험만 다룬다. 여러 개를 동시에 캐물으면 전부 얕아진다.

### 2. 캐묻기

질문은 한 번에 하나씩 한다. 사용자가 이미 말한 것은 다시 묻지 않는다. 아래 순서를 기본으로 하되 대화 흐름에 맞춘다.

1. 어떤 상황이었고 무엇이 문제였나
2. 내가 맡은 목표는 무엇이었나, 팀 규모와 구성은 어땠나
3. 내가 직접 한 것과 팀이 한 것의 경계는 어디인가
4. 선택지가 있었나, 왜 그것을 골랐나, 무엇을 버렸나
5. 잘 안 풀렸던 부분이나 방향을 바꾼 순간은 없었나
6. 결과는 어떻게 됐나. 숫자로 말할 수 있나, 그 숫자는 어디서 나왔나(근거 자료)
7. AI 도구를 썼다면 무엇에 어떻게 썼고 무엇을 판단해 고쳤나
8. 이 경험으로 달라진 점은 무엇인가

사용자가 안 말하는 부분을 특히 묻는다. 결과는 말해도 판단 지점은 빠뜨리고, 성공은 말해도 실패와 수정은 빠뜨리고, "팀으로 했다"고 하면서 내 몫은 흐리게 두는 경우가 많다. 답이 모호하면 "그때 숫자로는 어느 정도였나요", "그건 직접 하셨나요, 팀원이 했나요"처럼 구체적으로 되묻는다.

### 3. 카드 작성과 확인

[method.md](method.md) 의 7절 양식으로 카드를 만든다. 저장하기 전에 사용자에게 내용을 보여 주고 사실과 다른 곳을 고치게 한다. 규칙은 다음과 같다.

- 사용자가 말한 것만 적는다. 그럴듯하게 살을 붙이거나 표현을 부풀리지 않는다.
- 기억나지 않는 수치는 `⚠️ 미확인` 으로 두고 "확인 필요" 항목에 확인 방법을 적는다. 추측해 채우지 않는다.
- 같은 경험이 다른 카드나 문서에 이미 있으면 수치, 순위, 역할 표현이 일치하는지 대조하고, 어긋나면 어느 쪽이 맞는지 묻는다.

### 4. 역량 주제 태그

카드가 보여 줄 수 있는 주제를 사용자와 함께 정한다. 기본 예시(문제해결, 협업, 리더십, 실패 극복, 고객 이해, 데이터 활용, AI 활용)는 출발점일 뿐이다. 지원하려는 기업의 문항을 알려 주면 그에 맞게 주제를 추가하거나 바꾼다. 한 경험에 태그가 여러 개 붙어도 된다.

### 5. 인덱스 갱신

`${user_config.workspace_dir}/profile/experiences/_INDEX.md` 에 역량 주제 × 경험 표를 유지한다. 행이 경험, 열이 주제다.

```markdown
# 경험 인덱스

| 경험 (파일) | 문제해결 | 협업 | 데이터 활용 | 확인 필요 |
|---|---|---|---|---|
| [<경험 제목>](<슬러그>.md) | O | | O | 수치 1건 |
```

주제 열은 카드 태그에서 모은다. 어떤 주제에 경험이 하나도 없으면 빈 열로 두어 비어 있는 곳이 보이게 한다. 확인 필요 열에는 카드의 `⚠️ 미확인` 개수를 적는다. 새 주제가 생기면 열을 더하고 기존 카드에 해당하는지 사용자에게 묻는다.

### 6. 갱신

카드는 한 번 쓰고 끝이 아니다. 면접에서 받은 질문이나 새로 기억난 수치를 계속 덧붙인다. 사용자가 기존 카드를 다시 열면 `⚠️ 미확인` 항목부터 확인한다.

## 금지

- 자소서나 면접 답변 문장을 대신 쓰지 않는다. 카드는 재료이고 문장은 사람이 쓴다. 다음 단계에서 쓸 소재를 고르는 일은 돕는다.
- 사용자가 말하지 않은 사실, 수치, 역할을 만들어 넣지 않는다.
- 카드를 노션이나 다른 외부 서비스에 올리지 않는다. 고객사 기밀이나 개인 정보가 섞일 수 있으므로 작업 폴더에만 둔다. 사용자가 고객사명, 내부 수치를 말하면 카드에 그대로 적되 외부로 보내지 않는다고 알려 준다.
- 한 번에 여러 경험을 동시에 캐묻지 않는다.
